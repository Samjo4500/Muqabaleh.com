   112→### Design decisions
   113→- **Navbar**: Uses `useTranslations('nav')` + `useTranslations('common')` for all strings. Locale toggle uses `useRouter` + `usePathname` to construct locale-aware paths. Mobile menu uses shadcn `Sheet` with RTL-aware side (`left` for ar, `right` for en). Scroll state tracked via `useEffect` + `scroll` event listener.
   114→- **Footer**: Although spec said "server component", it uses `use client` + `useTranslations` because it's imported by the client-side landing page. Uses `useTranslations('landing')` for all footer-specific strings and `useTranslations('common')` for shared strings.
   115→- **Landing Page**: Single `'use client'` page with section sub-components defined inline. Each section receives only the `t` translation function (and `isRTL` where needed) as props to avoid unnecessary re-renders.
   116→- **Hero Preview Card**: Uses `useState` + `useEffect` with `setInterval(9000)` to cycle between `analyzing` and `complete` phases. In analyzing phase, shows animated progress bar + 4 ScoreBars. In complete phase, shows emerald checkmark.
   117→- **Country Marquee**: Uses `t.raw('marqueeCountries')` to get the raw array from i18n. Duplicates the list for seamless infinite loop. RTL direction uses `animate-marquee-rtl` class.
   118→- **Before/After**: Desktop uses Framer Motion `drag="x"` on the divider handle. Mobile falls back to stacked layout. The clip-path approach reveals the "before" and "after" cards.
   119→- **Interviewers Audio**: Uses native `<audio>` elements with `ref` for play/pause control. Waveform bars use `.waveform-bar` CSS class with staggered `animationDelay` and `animationPlayState` toggling.
   120→- **Pricing localApprox**: Uses next-intl ICU message format `t('localApprox', { sar: '...', aed: '...', ... })` for currency conversion display.
   121→- **All strings from i18n**: Every visible string uses `useTranslations`. No hardcoded Arabic or English in JSX.
   122→- **Responsive**: Mobile-first design with Tailwind responsive prefixes (`sm:`, `md:`, `lg:`). Touch targets meet 44px minimum.
   123→- **Sticky footer**: Root wrapper uses `min-h-screen flex flex-col`, footer uses `mt-auto`.

   360→### Design decisions
   361→- **B2B Layout**: Modeled after existing `app/layout.tsx` sidebar pattern. 260px width, bg-panel, border-s for RTL. Nav items use `border-s-gold` for active state (gold left border in LTR, gold right border in RTL). Mobile uses Sheet with locale-aware side (`left` for ar, `right` for en). Bottom section has sessions badge, company name, and sign out button.
   362→- **Onboarding**: Standalone page (no sidebar layout). Uses AuthShell-like pattern (aurora bg, centered card, logo). 3-step wizard with progress bar using `border-s` for gold highlight. Plan selection uses custom radio cards with `border-gold` + `bg-gold/10` for selected state. Email rows with add/remove (max 10).
   363→- **Dashboard**: 5 KPI cards in a 5-column grid (`lg:grid-cols-5`) using GlowCard. Uses plain number display instead of CountUpStat (which expects string). Activity list with gold dots and relative timestamps.
   364→- **Jobs List**: Desktop table + mobile card fallback. Status badges use color-coded border/bg/text classes. Jobs link to candidates page via `/b2b/jobs/${i+1}`.
   365→- **New Job Form**: Conditional rendering for Human mode (shows assignment mode radio + panel interviewer selects). Must-ask questions with add/remove (max 5). File upload input (visual-only) + download template link. All from i18n.
   366→- **Candidates**: Desktop table with 9 columns + mobile cards. Click handler on rows with scores opens Dialog report modal. Report modal includes score circle, ScoreBars, recommendation badge, AI feedback, strengths/improvements, and company criteria section (matching C4 report format plus company criteria). Status badges color-coded per status type.
   367→- **Team**: Desktop table + mobile cards. Invite uses shadcn Dialog with email + role select. Role badges: Admin (gold), Member (muted).
   368→- **Billing**: Balance card with large gold number + CreditCard icon. Invoices table with paid/pending status badges.
   369→- **Settings**: Three GlowCard sections: company info (pre-filled form), panel interviewers (removable list items), SLA settings (hours input + custom text). Uses `tAuth` for reusing existing sector/country/size translations from `auth` namespace.
   370→- **Demo/Guest**: Both standalone (no layout wrapper). AuthShell-like pattern with aurora bg. Guest page has two states: form and confirmed.
   371→- All pages: Responsive mobile-first. RTL-aware with logical CSS properties (`border-s`, `ps-`, `pe-`, `ms-`, `me-`). Touch targets 44px minimum.
   372→- All strings from i18n. No hardcoded text. No emojis. Lucide icons only with `strokeWidth={1.75}`.
